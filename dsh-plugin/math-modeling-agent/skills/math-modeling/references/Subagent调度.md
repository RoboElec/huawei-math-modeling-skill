# Subagent 调度与阶段门禁

Subagent 是阶段内临时协作者，不是第四个固定角色。主 Agent 负责统筹、写入权威产物和处理返工；质检 Subagent 必须未参与被审产物的编写，并默认只读。

## 默认策略

1. 默认仅派发下表中的固定质检 Subagent；调研、原型和并行实验等可选协作默认关闭。
2. 只有用户明确启用具体任务或类别时才派发可选 Subagent。用户未选择时不要反复询问，也不要暂停主流程等待授权。
3. 用户可随时增加、缩小或关闭可选协作范围；未明确启用的类别始终保持关闭。
4. 可选 Subagent 只返回范围、输入、证据或实验产物、结论、未知项和建议，不直接修改权威交付物；主 Agent 负责取舍和整合。

示例：`额外启用官方规则、附件盘点和文献调研 Subagent`、`只启用算法原型 Subagent`、`除固定质检外不使用其他 Subagent`。

## 强制原则

1. 禁止等全流程结束后才首次派发质检 Subagent；在下表规定的节点及时验收。第一次失败后先修复已编号阻塞项；第二次仍失败则停止自动返工。只有用户显式 `HUMAN_OVERRIDE` 接受风险时，才允许在保持失败状态记录的前提下继续后续工作。
2. 作者自检、脚本校验和独立验收三者不能互相替代。已有脚本负责机械检查，Subagent 负责独立复现、语义和证据审查。
3. 质检 Subagent 不直接修改固定交付物，只返回带证据的问题；原阶段执行者修正后，由未参与修正的质检 Subagent 复验。
4. 仅当变化实际触及该门禁的受审合同、关键数值、约束、复现链或证据时，相关 `PASS` 才失效；纯措辞、排版、美化、文件重排不得级联触发全流程重审。
5. 单阶段任务只运行该阶段的门禁，不强制拉起完整三阶段。
6. 运行环境没有 Subagent 能力时，继续运行确定性脚本并明确报告“独立验收未完成”，最终状态只能是 `BLOCKED` 或受限交付；不得声称全部门禁通过或完整完成。

## 竞赛安全：复验预算、问题指纹与人工熔断

真实竞赛默认执行本节；除非用户在看到未解决问题后明确增加某一门禁的复验预算，否则本节优先于一般性的“失败后继续复验”。

1. **每个固定门禁最多 2 次独立质检**：第 1 次为 discovery review（全量发现审查），第 2 次为 regression review（回归复验）。达到上限后禁止自动派发第 3 个及后续质检 Subagent。
2. **第一次审查必须稳定编号问题**：每个阻塞性 `P0/P1` 分配稳定 ID，例如 `M1-001`、`P2-003`，记录证据、影响和验收条件；`P2` 默认只作为非阻塞建议。
3. **第二次只做回归复验**：只检查上一轮 `P0/P1` 是否关闭，以及本轮修正是否直接引入新的 `P0`。第二次新发现、且并非由修正直接引入的普通 `P1/P2` 记录为建议，不得据此再次阻塞或触发第三轮审查。
4. **预算耗尽即人工接管**：第二次后仍有上一轮未解决的 `P0/P1`，或修正直接引入新的 `P0` 时，门禁保持 `FAIL` 并标记 `AUTO_RETRY_EXHAUSTED`。主 Agent 必须停止自动返工，汇总“问题 ID—证据—影响—建议—当前最佳版本”，等待用户决定。
5. **禁止 reviewer preference 形成死循环**：额外美化、更多候选图、额外敏感性分析、措辞偏好、模型“还能更高级”、非必要创新默认属于 `P2`；只有影响数学正确性、官方硬约束、关键复现或主张—证据一致性时，才能升级为 `P0/P1`。
6. **支持人工冻结**：用户可设置 `MODEL_FROZEN`、`RESULTS_FROZEN`、`PAPER_FROZEN`。冻结后只能提出建议，不得自行修改对应权威内容；若发现新的 `P0` 或官方硬约束冲突，先报告证据并请求用户解冻，不得自动解冻。
7. **人工决定高于自动优化**：用户确认保留某个模型、结果或可提交版本后，不得仅因为“存在更优方案”而推翻；除非出现可验证 `P0` 或用户主动要求重新比较。
8. **显式人工覆盖**：出现 `AUTO_RETRY_EXHAUSTED` 后，用户可明确使用 `HUMAN_OVERRIDE:<门禁>` 接受已列明风险并继续。覆盖后该门禁记录为 `FAIL_ACCEPTED`/`HUMAN_OVERRIDE`，绝不能改写为 `PASS`；最终交付必须列出被接受的风险和证据。

## 固定门禁

| 门禁 | 派发时机 | 质检重点 | 通过后才能 |
|---|---|---|---|
| `M1` 建模终检 | 两个建模产物完成作者自检后 | 子问题覆盖、假设依据、公式与符号、符号数学排版、单位与约束、模型数量、可实现性、验证方案、文献可追溯性 | 进入编程或交付建模产物 |
| `P1` 最小可运行结果 | 数据读取、预处理和核心求解链首次跑通后 | 从 `PROJECT_ROOT` 执行最小命令；核对真实输入或等价小实例、退出码、关键结果、单位、范围、约束和模型合同 | 开始全量计算、正式出图和参数扫描 |
| `P2` 编程终检 | 代码、结果表、用于支撑各子问题结论的证据图表与复现清单冻结后 | 独立复现、输入哈希、随机种子、关键数值、边界与量纲、证据图表语义、建模流程图真实性与覆盖、复现清单和文件完整性；不按固定图数验收 | 进入论文阶段或交付编程产物 |
| `W1` 证据大纲 | 主张—证据映射和论文大纲完成后 | 每个子问题的结论都有公式、结果表位置、图文件、代码输出或已核验文献；符号说明表、附录计划、完整代码要求和总体建模流程图完整；用户显式要求 LaTeX 时两种格式共用同一证据源 | 开始长篇正文和排版 |
| `W2` 论文终检 | 用户要求的全部论文格式内容冻结且各自确定性门禁完成后 | 当届规则、主张—证据、数值与单位、符号数学排版、附录边界与引用、要求附完整代码时的源码完整性和可运行性、总体建模流程图真实性与入文、其他图表引用、文献、Markdown 格式残留、支撑材料完整性和实际渲染；同时生成两种格式时再检查 Word/LaTeX 一致性 | 按用户要求交付 Word（`完整论文.docx`）或 LaTeX/PDF（`完整论文-LaTeX/` 与 `完整论文.pdf`）；真实竞赛仍须提醒用户上传并确认成功 |

`P1` 是纵向切片，不要求三类图、完整敏感性分析或最终性能。`W1` 是内部检查，不新增固定交付物。每个阶段可由同一名始终未参与编写和修正的质检 Subagent 连续执行中途门禁与终检；不要为每个函数、每张图或每个段落重复派发。

## 派发输入

只提供完成当前验收所需的原始证据：

- 用户要求、题目和只读附件路径。
- 当前门禁的验收条款和权威产物路径。
- 输入文件版本或 SHA-256、官方规则来源、关键命令与日志。
- 上一门禁回执；复验时再提供原问题及修正证据。

不要先告诉质检 Subagent“主 Agent 认为已经正确”，也不要给出期望的通过结论。质检范围外的历史对话不传入，避免结论污染。

## 固定回执

质检 Subagent 只返回：

1. `范围`：本次检查的门禁和未覆盖内容。
2. `输入快照`：路径、版本或 SHA-256。
3. `状态`：`PASS`、`FAIL` 或 `BLOCKED`。
4. `证据`：来源 URL、命令、退出码、文件位置、页码或关键数值。
5. `发现`：按 `P0`（正确性/官方硬约束）、`P1`（复现/一致性/关键质量）、`P2`（非阻塞改进）列出。
6. `返工`：应回到的角色、必须修正项和复验入口。

第一次 discovery review 中存在未解决 `P0/P1` 时返回 `FAIL`；第二次 regression review 只允许上一轮未关闭的 `P0/P1` 或修正直接引入的新 `P0` 继续阻塞。缺少依赖、权限、输入或可验证证据时返回 `BLOCKED`。主 Agent 不得把 `FAIL` 改写成通过，也不得在复验预算耗尽后自动开启新一轮。

## 用户可选协作（默认关闭）

| 任务 | 触发条件 | Subagent 输出 | 并行与边界 |
|---|---|---|---|
| 当届官方规则核验 | 竞赛、届次或模板尚未核验 | 官方 URL、适用届次、硬约束、模板路径与哈希、冲突和未知项 | 可与附件盘点并行；论文构建必须等待 |
| 数据附件盘点 | 多附件、复杂 PDF/Excel 或字段较多 | 文件哈希、工作表、行列、首末行、字段、单位、缺失和异常 | 只读；模型选择须等待关键数据事实 |
| 文献与模型族调研 | 主张、关键词或候选模型族已经明确 | 题名、作者、年份、DOI/出版页、理论公式、适用条件、所需数据和失败风险 | 按主张簇或模型族拆分；不要按搜索引擎拆分，最终模型取舍仍由主 Agent 完成 |
| 隔离算法原型 | 某个候选算法的可实现性、接口或复杂度需要验证 | 独立目录中的最小代码、运行命令、真实输出、限制和未解决问题 | 不修改权威代码；原型通过后由主 Agent 决定是否整合 |
| 独立实验批次 | 模型、指标和参数范围已经冻结，实验之间互不依赖 | 参数、种子、命令、结果文件、耗时和失败记录 | 可并行敏感性、消融或边界实验；不得边改模型边跑实验 |
| Python/MATLAB 对照实现 | 用户明确要求双语言或需要验证跨语言一致性 | 各自隔离的实现、命令、环境、关键数值和差异 | 使用同一模型合同和输入输出；主 Agent 统一权威结果 |
| 术语与英文表达核验 | 专业领域术语较多或生成 MCM/ICM 英文论文 | 术语对照、符号与单位冲突、建议修改位置和来源 | 只提供建议，不分章节并写论文 |

## 不委派或不并行

- 不让多个 Agent 同时修改 `题目分析报告.md`、`术语表格.md`、权威代码、结果或论文正文。
- 不按章节多人并写论文，不分别生成互不共享正文的 Word 与 LaTeX。
- 不把模型取舍、假设与阈值裁决、跨题耦合、用户授权和最终交付范围交给任何 Subagent。
- 依赖检查、哈希、编译、DPI、SVG 文本和文档结构等已有脚本覆盖的机械任务直接运行脚本，不再增加 Subagent。
